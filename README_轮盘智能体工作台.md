## 启动应用

双击工程根目录的 `start_disk_agent.cmd`，它会启动隐藏的本地服务并打开默认浏览器。再次双击会复用已启动的同一服务。默认地址：

```text
http://127.0.0.1:8765
```

也可在 PowerShell 中以前台方式运行，便于看日志：

```powershell
Set-Location -LiteralPath 'D:\DSV_20261022_1'
& 'C:\Users\18940\.conda\envs\llm_opt\python.exe' -B -m agent_app --app
```

端口被其他应用使用时，可改用 `--app --port 8766`。双击启动器的服务日志与进程编号在 `agent_app_logs/`。关闭浏览器不会停止任务；服务需要继续运行。前台方式可在空闲时用 Ctrl+C 结束服务。

## 页面操作

1. 输入明确任务，例如“新建优化4个候选”。
2. 点击“预览任务”，检查任务单与目标候选预算。默认关闭“规划 LLM”，用离线规则理解任务。
3. 需要实际计算时，点击“开始真实计算”。它允许原优化 LLM 和 Workbench 执行；同一预览任务会使用原工作流继续执行。
4. 从工作流列表查看规划、校验、计算、分析等阶段及候选进度。失败或中断后，可选择原工作流预览恢复条件，再点击继续计算。
5. 从已有运行列表选择历史 run，查看实测应力曲线、最优参数对应指标、面积变化、成本及工程约束状态。页面上的历史分析默认不重新核验原生文件，并明确显示证据状态。

规划模型与优化执行是两个独立开关。开启“规划 LLM”会增加任务理解阶段的 API 请求；点击真实计算才允许优化求解。文本明确要求“只看计划/先别实算”时，该工作流仍只生成计划，需要用新的明确执行请求创建任务。

## 工作流与预算

```text
自然语言或 TaskSpec
  → planner / TaskSpec
  → 工作流状态持久化
  → 案例与预算校验
  → 环境预检
  → 执行一批（原工具 → 原控制器 → 原 LLM/Workbench）
  → 核验已提交记录并分析
  → 预算内下一批，或生成完成报告
```

默认每批沿用搜索配置的4候选边界。例如6候选任务以目标总数4、6分两次调用现有执行器；若已有1候选，追加3候选仍会复用同一批计划。总体目标在首次校验时固定为绝对总候选数，恢复时不会重复叠加 additional budget。效果没有改善也不会自行增加预算。

任务状态与求解断点分别保存：

```text
agent_workflows/wf_.../state.json          工作流任务、阶段、冻结预算与运行绑定
agent_workflows/wf_.../analysis.json       最新结构化分析
agent_workflows/wf_.../analysis/batch_*.json 每个批次的分析
agent_workflows/wf_.../report.md           中文评价报告
python_llm_runs/run_.../checkpoint.json    原控制器求解进度与已提交结果
```

已保存的工作流不携带真实执行权限，每次恢复仍需显式 live。进程在求解期间退出后，恢复沿用保存的 run_id 与 pending 批次，不使用全局 latest 指针猜测。如果此前调用未成功绑定 run，返回 needs_review，避免盲目认领其他运行。

工作流锁和引擎项目锁继续生效。应用内一次只接收一个后台任务；忙时返回明确提示，不自动排队重复启动。若引擎或工程配置改变，旧工作流的真实恢复会拒绝执行。查询历史状态与分析原有结果仍可单独使用。

## 评价结论与成本口径

报告分别说明：

- 原生记录是否重验、求解是否完成；
- 应力是否优于基准和历史最佳，以及分析窗口内的改善；
- 位移和参数公式近似截面积的变化；
- 已实现搜索规则与尚未实现的工程约束；
- API 请求、token 覆盖情况及 Workbench 评价任务记录。

面积为近似截面积，不等于质量。当前未设置许用应力、质量、寿命等约束；应力下降不代表强度或寿命合格。分析器不根据九个尺寸的同时变化推断已验证热点或物理因果关系。

模型成本只统计原始调用日志：中心策略读取 `search/generation_*/center_api/request_*/proposal_*`，直接提案策略读取 `iterations/iter_*/api/request_*/proposal_*`。每候选目录复制的回答不重复计数。HTTP 尝试按 started 事件计数；usage 明细不再次加到总 token。缺失/损坏日志、失败投递或缺失 usage 会标为未知或部分已知。费用未换算为货币，也不混入规划器日志或其他运行。

报告中的模型成本是绑定 run 的累计值，不是某个工作流新增加的费用。恢复已有 run 时，累计值可能含该工作流开始前的调用。Workbench 的“1基准+4候选”指5个评价任务，不等同底层求解器恰好求解5次。

## 自动故障恢复

工作台新增默认勾选的“启用自动故障恢复”。点击“开始真实计算”或“继续真实计算”后，恢复协调器会读取错误、原生断点和HTTP传输记录，核对原工作流及候选预算，在满足条件时等待后续算，再检查故障候选是否已提交。

首版自动处理候选尚未生成时的HTTP 500、502、504服务错误。认证失败、限流、投递状态不明、几何或有限元失败，以及兼容性或记录校验失败，会显示需要人工检查及具体原因。HTTP 429、503暂由人工检查，现有终态日志未保存可供恢复器核验的Retry-After信息。

直接LLM尺寸模式现增加边界处理。每次请求突出各变量上下限和已经触及边界的变量，并使用带数值范围的提案Schema。沿用已配置的LLM纠错次数，最后一次仍越界时，允许将超出量不大于该变量范围5%的数值修正到最近边界。例如Y1范围40–50mm，39.6mm可修正到40mm。修正后重新执行九参数、有限数、四位小数及历史重复检查。原提案、实际尺寸和修正原因写入`proposal_*/repair.json`及候选的`automatic_boundary_repair`字段，优化轨迹显示“边界自动修正”。

持续越界时，恢复器核对最终回答、拒绝记录、请求清单、传输成功证据和待处理断点，确认该候选尚未进入仿真后，按下述次数与HTTP预算重新请求。修正后重复或超过5%修正阈值的提案也受该预算限制。已保存的目标及质量/频率配置会在恢复检查前绑定。可恢复的提案失败在原候选序号上继续处理。

重复提案同样支持有上限的自动恢复。系统把被拒绝的九参数、对应历史记录编号、四位小数量化规则和最小归一化距离反馈给LLM。断点续算时会读取本候选先前请求的重复拒绝记录，帮助新请求避开刚刚重复过的方案。新尺寸继续由LLM提出，通过原去重校验后才送入Workbench。失败的重复提案保留请求与成本记录，已完成候选数在成功求解提交后增加。

提案字段兼容明确的中文别名，`参数`映射为`parameters`，`理由`映射为`rationale`，`候选类型`映射为`candidate_type`，枚举`利用`、`探索`分别映射为`exploit`、`explore`。规范化仅处理这些已知标签，记录于`proposal_*/schema.json`和候选的`automatic_schema_normalization`。同一字段同时出现中英文名称时交给原校验器拒绝。原始响应、规范化后的回答和后续校验记录均可追溯。

尚未生成候选的JSON格式、必需字段和数值类型错误也可以进入有上限的重新提案流程。恢复前按相同规则核对最终回答、拒绝原因、零仿真请求及断点证据，恢复次数与HTTP请求预算共同限制后续调用。

默认限制按以下口径执行。

- 同一故障最多自动恢复2次，等待时间依次为30秒、120秒。
- 单工作流最多自动恢复6次，累计预留等待最多600秒。
- 同一待处理中心请求最多10次HTTP尝试，包含已有手动重试和底层重试。每次恢复前按底层请求配置预留最坏HTTP次数，余额不足时提前停止。
- 恢复记录绑定原工作流、运行、待处理候选和冻结预算。次数与等待截止时间写入磁盘，重启后继续计数。

故障面板展示判定原因、已完成和剩余候选、重试次数、HTTP次数、倒计时及恢复事件。等待期间可点击“停止自动重试”，取消后续恢复。服务重启后需要再次点击“继续真实计算”才能恢复执行。恢复中断于HTTP请求期间且回执不完整时，需要先核对记录。

已恢复或已完成时，旧错误显示为中性的“已恢复的历史记录”，当前错误字段清空。实时断点中的错误优先于上一批分析。用户明确点击“继续真实计算”时，已保存的有效提案、求解结果及已完成批次可以交回原调度器续算或重新生成分析报告；调度器继续执行原有兼容性、预算和原生结果校验。请求尚未生成有效候选时，按恢复证据与请求次数限制处理。

| 文件 | 职责 |
|---|---|
| `agent_app/recovery_evidence.py` | 只读检查错误资格、兼容性、断点与原始HTTP证据，统计同一故障的请求次数 |
| `agent_app/recovery.py` | 持久化恢复预算、等待、同工作流续算、停止响应及恢复后核验 |
| `agent_workflows/wf_.../recovery.json` | 运行时生成的恢复状态与事件记录 |

页面查询、刷新和服务启动只读取恢复状态。此功能通过工作台真实执行接口启用，现有CLI参数保持原行为。开发验证采用隔离HTTP与有限元替身，真实运行由用户在工作台显式继续。

## 可配置目标与约束

工作台上方提供目标与约束面板。选择应力优化、质量优化或应力—质量双目标模板后，输入候选预算并点击“预览任务”。例如输入“新建优化4个候选”，目标方向和权重由面板配置确定。

每个指标分别配置优化方向与约束。约束支持绝对值或相对基准百分比。相对值100%对应本次运行的基准值，95%对应基准值的0.95倍。启用约束后需要填写限值及其依据，未完成的设置可以保存为浏览器草稿。

每个工作流和搜索批次保存配置版本。修改权重、方向或限值后创建新任务。已有运行可以使用“重评选中运行”按新设置筛选和排序，重评结果保留在页面，原始计算记录与任务配置保持原值。

“目标与可行方案”页签展示各记录的应力、质量、频率、约束状态、基准归一化评分、目标推荐和Pareto记录。硬约束先决定可行性，评分用于可行方案之间的排序。缺少目标或约束所需数据的记录显示“数据缺失”，可行方案为空时推荐记录为空。

已有单应力运行可继续读取。其历史中没有采集的质量或频率保持缺失状态。二维面体的Body.Mass与Geometry.Mass可返回0，因此整盘质量由Mechanical真实截面面积、形心半径和Engineering Data材料密度计算。程序同时核对MAPDL的360°轴对称质量汇总，单位换算为kg，相对差要求不超过0.1%。本机基准与一个候选的真实质量验收已完成。

选择多指标目标后，GP按所需指标分别训练和验证。应力沿用已有MPa门槛，质量与频率的绝对RMSE门槛暂设为各自基准值的5%，同时检查归一化交叉验证误差。任一所需模型不可用时，候选筛选回退到现有空间覆盖规则与分组配额。当前影子预测页继续展示应力预测记录。

本机已建立并真实求解工作转速下的预应力轴对称工程，位于`project_modal/2dmodel.wbpj`。启用频率后，任务自动绑定该独立工程，分析名称为`DiskAgent Prestressed Axisymmetric`，当前可选择1～6阶。静力工况沿用1349.3 rad/s转速与-131.85 MPa外缘压力。任务会核验模态预应力指向同一静力来源。当前接口按固定阶次取值，跨阶振型跟踪仍待独立开发验证。

## 运行体检与保护

工作台提供“新任务体检”和“所选运行体检”。新任务使用当前目标面板配置，所选运行使用保存的配置和预算，并复核续算兼容性。优化启动前会执行环境检查。输出写入失败、密钥配置缺失、工程占用等确定性问题会阻断启动。可用空间低于5 GiB时提醒，许可证服务连接与实际功能授权分别展示检查结果。

原生评价启动前保存固定评价编号、目录和请求摘要。阶段记录覆盖几何更新、设计点求解、原生核验、质量及模态采集。默认阶段观察阈值为30分钟；积累至少3份同配置阶段记录后，按近期最大耗时的3倍加60秒计算，最少180秒。超过观察阈值时显示耗时提醒。恢复时核对原进程的PID和创建时间，完成标记与原生结果全部通过后接收已有结果。

几何预检检查五段正跨度、四处正半高、六站点顺序和现有截面积公式。网格诊断记录可取得的单元质量与Jacobian统计。未取得有效网格或统计接口不可用时显示原因。当前按诊断模式使用，制造最小厚度、完整CAD轮廓自交和网格工程验收门槛待提供依据。应力相对基准或上一实测变化达到25%时生成复核提醒。

每次提交结果后保留最近5份通过结构与原生证据核验的断点，备份含SHA256摘要。“已核验断点备份”可查看备份并预览恢复。恢复只接受最新有效备份，并检查配置指纹、当前断点摘要、项目占用和未结算现场。有关联工作流时，先移除关联工作流列表记录，再执行恢复。旧备份可用于核对记录。

上述检查通过确定性程序执行。新增保护涉及控制器版本，历史运行的续算需通过原有版本与工程指纹核验。页面中的历史结果可继续读取。
