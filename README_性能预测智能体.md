# 性能预测智能体第一版：GP封装与影子验证

日期：2026-11-05。

本阶段把现有高斯过程模型封装为可检查的性能预测节点，并接入轮盘工作台。新增节点只做影子预测和误差追踪，不改变原优化器的候选、缓存计划或预算，也不增加大语言模型请求。

## 如何查看

启动现有 `start_disk_agent.cmd`，打开 http://127.0.0.1:8765/ ，选中工作流或已有运行，进入“性能预测”页签。点击“刷新预测记录”读取最新状态。普通3秒进度轮询不会反复训练模型；只有进入页签、切换运行或显式刷新才检查。

当前真实运行 `run_20261104_220450_b58875bbd565` 有1个基准和4个候选，共5条唯一实测，低于24条训练门槛。页面应显示“数据不足”，4个旧候选没有事前预测，不生成预测值或误差。本阶段没有为已有结果事后补造预测。

## 三个文件的职责

| 文件 | 职责 |
|---|---|
| `agent_app/performance_predictor.py` | 统一输入、验证数据与模型、复用原GP，返回模型状态/应力预测/后验标准差/数据距离和版本签名；提供只读运行检查 |
| `agent_app/prediction_audit.py` | 在新候选有限元调用前保存不可变预测记录；恢复时核验并复用；只读匹配已提交实测并计算误差 |
| `agent_app/tools.py` | 在原候选FEA入口调用预测审计，位置在已有反馈来源核验之后、真实求解之前 |

工作台新增只读端点 `GET /api/runs/<run_id>/predictions`，不增加可以任意改工程配置或启动求解的预测接口。`web.py` 和 `static/index.html` 负责展示。

## 状态与数值的含义

- `no_baseline`：尚无已提交基准。
- `insufficient_data`：唯一实测数量低于现有配置门槛；不拟合、不输出数值预测。
- `validation_failed`：原GP交叉验证/前向留出未通过，或数值计算不可用；不输出数值预测。
- `ready`：原模型门禁通过，可以提供影子预测；这不是工程准确性保证。
- `unavailable`：读取、工程兼容性、原生结果或审计来源检查未通过；不能据此判断预测效果。

预测输入沿用九参数、四位小数和原模型的mm数值约定；不裁剪、不自动改单位，不把重复设计凑成新样本。训练数据只取同一运行已提交的有限元观测，并检查原工程定义、指纹和原生结果来源。不混入预测值、未提交pending结果或其他不兼容运行。

当前最低门槛保持24条；还需通过原4折交叉验证与前向留出验证。样本门槛不是九维问题的数据充分性保证。按每批4个候选，原选点器各代的起点样本数为1、5、9……25，通常在累计24候选和1基准后首次尝试GP。

目前只预测最大等效应力。位移、强度许用值、质量和寿命不在模型输出范围；近似截面积仍是公式值，不等于质量。GP标准差没有做覆盖率校准，不能表述为95%可靠区间。

## 预测如何与有限元比较

```text
原优化器确定候选
  → 已提交历史快照
  → 本地GP状态检查与影子预测
  → 原子保存 prediction_audit/iter_001.json
  → 原Workbench评价与原控制器提交
  → 页面只读匹配候选编号、参数和提交结果
```

每条事前记录包含运行、候选、生成时间、几何、历史前缀签名、模型代码/数据/问题/配置签名。原始记录不可改写；恢复同一候选时沿用原记录，不拿后来的结果重新训练并替换预测。来源不符或记录写盘失败时阻止新候选FEA，避免产生无法追溯的预测声称；模型数据不足或验证失败则正常记录“无数值预测”，继续原求解。

比较只使用控制器已提交结果。pending即使已经有detail，也不当作已提交实测；读取页面不写任何结果文件。结果提交后，候选编号与历史前缀重新核对，动态计算：

```text
误差 = 有限元应力 − 事前预测应力
绝对误差 = |误差|
相对误差(%) = |误差| / 有限元应力 × 100
```

MAE、RMSE和最大绝对误差仅统计存在有效事前数值预测且已有已提交实测的配对记录。不对无预测的旧记录计算误差，不把缺失当作0误差。

页面展示当前数据下的模型状态，以及各候选当时的事前记录；二者可能不同。例如当前已ready，早期候选当时仍为数据不足。每条记录均保留当时的模型状态。

## 与原GP选点的关系

原 `python_control/surrogate.py` 已有GP选点能力，本阶段没有修改它。原选点器按每代冻结的basis_history生成并缓存计划；新影子节点在每个候选求解前使用当时全部已提交历史。两者的数据时点可能不同，页面的影子预测不冒充原批次排序依据。

原GP是否参与选点，仍由现有 `center_surrogate` 配置和原门禁决定。新增节点不额外批准或禁止原GP策略。未来调整选点算法，应在相同有限元预算下比较，再单独实施。

## 成本与边界

本地NumPy GP拟合和预测不消耗LLM token，不增加模型请求。本阶段没有将预测长表加入LLM提示词。固定每批4个真实候选时，影子验证不减少该批FEA数量，其作用是为后续判断预测质量提供证据。

开发测试中的HTTP和有限元均为替身。真实历史仅只读核验，本阶段没有新增真实API或Workbench评价。模拟预测误差、平滑合成数据GP验证通过，都不能作为真实轮盘泛化误差或优化收益证据。
